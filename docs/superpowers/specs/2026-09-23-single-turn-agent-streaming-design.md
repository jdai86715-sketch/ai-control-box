# 单轮逐步 Agent 流式设计

## 目标

让 Qwen 在一条用户消息内自行连续完成工具任务，并将真实执行过程与最终文字实时显示在 WebUI。

## 已确认边界

- 只处理用户发起的单轮，不后台自主运行。
- 每次只执行一个原生 `tool_call`；工具结果回喂后，由同一 Qwen 上下文决定下一步。
- 一轮最多五步。这是防止意外无限循环的技术预算，不是工具权限或候选白名单。
- 每一步都从热插拔 ToolRegistry 重新生成原生 `tools`；执行时仍由注册表按名称解析。
- 不展示私有思维链。界面显示可审计的事件：步骤、工具、参数、结果与模型正在生成回复。
- 最终文字使用 llama-server 的真实 token stream；不保留完成后再假流式播放的机制。

## 协议

浏览器以 `POST /api/chat/stream` 发出指令，服务端以 SSE 返回：

- `turn_start`：创建过程区域
- `text_delta`：模型文本 token
- `tool_call`：完整原生调用已解析，可执行
- `tool_result`：动态注册表执行后的 JSON 结果
- `done`：耗时、工具 schema 数、已执行步数
- `error`：本轮无法继续时的中文错误

`text_delta` 如果随后出现 `tool_call`，前端将其归入过程区域；没有工具调用时，它就是最终自然语言回复。

## 验收

1. 普通问题以真实 token 逐步显示，不显示“没有匹配的工具”。
2. 时间、天气、灯光等请求显示一次 `tool_call`、一次 `tool_result`，再逐 token 显示最终回复。
3. 每个新步骤只执行一个调用；五步后停止继续调用并显示已取得的回复或明确错误。
4. 完成后过程区域自动平滑折叠；展开后仍可看到真实调用与结果。
5. Needle 既有同步接口保持可用；流式逐步循环用于 Qwen 原生 tools 路径。
